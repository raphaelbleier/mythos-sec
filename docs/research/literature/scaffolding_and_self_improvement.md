# Agent scaffolding vs base model, and experience-replay / self-improving agents: ablation evidence as of 2026-11-13

Reading rules for this file. Source class is tagged: [PR] peer-reviewed venue (per venue listing or search result, not re-checked against proceedings), [PP] arXiv preprint, [WS] workshop (non-archival), [VENDOR] vendor self-report, [2ND] secondary page (blog, aggregator, mirror) that I could not check against the primary. "n" is the task or run count; "SE" is a binomial standard error I computed myself (labelled "my calc"), not something the paper reports. Where a number has no n or no baseline it is marked UNSUPPORTED. Effort limit: I read abstracts and HTML renders through a summarising fetch tool, so table values below are as the tool reported them; several pages were truncated after ~100k characters (noted). Nothing here was invented; whatever I could not find is in the Gaps lists. Model names such as "Claude Fable 5", "Opus 4.8", "GPT-5.5", "Opus 5" are quoted as the sources print them; I did not independently confirm those models exist.

## A1. Which scaffolding components have measured ablations (playbooks/skills, planning, verification/critic, memory/retrieval, tool breadth, completion pressure)

### Takeaway
The best-measured components are (a) curated procedural skills in context (SkillsBench: +16.2 pp mean over 84 tasks, but self-written skills give nothing and software-engineering tasks gain only +4.5 pp), (b) tool-layer abstraction in security (Incalmo, PentestGPT v2), and (c) in-run memory (+5.6 pp in AHE, +8 pp in PentestGPT v2). Explicit planning, critic/self-verification and anti-early-quit mechanisms have thin or no isolated ablations; the best-known self-verification result is negative (no gain without external feedback). Several popular components (repo-level instruction files, external knowledge bases in pentest agents) show zero or negative effects.

### Cited Findings
**Playbooks / skills / instruction files in context**
- SkillsBench [PP; also listed as a NeurIPS 2026 poster]: 84 tasks (abstract says 86; the paper is internally inconsistent), 11 domains, 7 agent-model configs, 5 trials/task, 7,308 valid trajectories, temperature 0. Mean pass rate: no skills 24.3%, curated skills 40.6% (+16.2 pp), self-generated skills 21.5% (-1.3 pp on the 5 configs where run; Table 3 says -1.8 pp). Per config no-skills to curated: Claude Code/Opus 4.5 22.0 to 45.3; Claude Code/Opus 4.6 30.6 to 44.5; Codex CLI/GPT-5.2 30.6 to 44.7; Gemini CLI/Gemini 3 Flash 31.3 to 48.7; Claude Code/Haiku 4.5 11.0 to 27.7. Domain gain ranges from +51.9 pp (healthcare) to +4.5 pp (software engineering). 16 of 84 tasks got worse (worst -39.3 pp). 2-3 skills best (+18.6 pp), 4+ skills +5.9 pp, "comprehensive" skills -2.9 pp. Confidence intervals are referenced in an appendix I could not read. — [arXiv HTML](https://arxiv.org/html/2602.12670v1); [NeurIPS listing](https://neurips.cc/virtual/2026/poster/139353)
- Repo-level context files (AGENTS.md style) [PP, listed at ICLR 2026]: Gloaguen, Mündler, Müller, Raychev, Vechev report that context files generally lower task success versus no context and raise inference cost by over 20%; developer-written files gave about +4% on their AGENTBENCH; agents do follow the instructions (more exploration/testing) but files do not shorten the path to relevant files. Figures come from search summaries, not the paper body (UNVERIFIED magnitudes; an aggregator quoted a 0.5-2% drop for LLM-generated files that I could not verify). — [arXiv PDF](https://arxiv.org/pdf/2602.11988); [ICLR listing](https://iclr.cc/virtual/2026/10018749)
- AHE (Agentic Harness Engineering) [PP]: system prompt alone gave 67.4% vs 69.7% seed on Terminal-Bench 2 (-2.3 pp, 89 tasks; ~2 tasks, inside noise); see memory/tools below. — [arXiv HTML](https://arxiv.org/html/2604.25850v2)

**Explicit planning**
- PentestGPT v2 / Excalibur [PP, authors' own system]: cumulative ablation on GPT-5.2 thinking: Base 54 / 8 / 2 (XBOW % of 104 tasks / PentestGPT-Bench machines of 13 / GOAD hosts of 5); + tool layer 68 / 9 / 2; + TDA-EGATS (task-difficulty-aware planner) 77 / 11 / 3; + memory 85 / 12 / 4. Planner increment: +9 pp XBOW (about 9-10 tasks), +2 machines, +1 host. 3 trials per cell, temperature 0, stated variance +-2-3% on XBOW. Table is cumulative, so each increment is order-dependent and was measured by the system's authors. — [arXiv HTML](https://arxiv.org/html/2602.17622)
- "Autonomous LLM Agents & CTFs: A Second Look" [PP, Bouchari et al., submitted 29 Apr 2026]: 30 web CTF challenges, 14 vuln classes, no public solutions; claims "structured orchestration of specialized roles outperforms monolithic designs", better run-to-run consistency, lower cost. Per-architecture solve counts, backbones and run counts are NOT on the abstract page (UNSUPPORTED as a quantified delta). Its general-purpose baseline claude-code solved 19/30. — [arXiv abs](https://arxiv.org/abs/2605.21497)
- Generative Agents [PR, UIST 2023 per search result]: planning, reflection and observation each ablated; 100 human evaluators ranking believability (TrueSkill); removing any component lowered believability. This measures believability of simulated humans, not task success. An alphaXiv summary gives full-architecture mu = 29.89 (I could not confirm). A PREreview reviewer calls the evaluation largely qualitative. — [Google Research page](https://research.google/pubs/generative-agents-interactive-simulacra-of-human-behavior/); [alphaXiv overview](https://www.alphaxiv.org/overview/2304.03442v2); [PREreview](https://prereview.org/reviews/17993733)

**Self-verification / critic / reflection**
- Huang et al. [PR, ICLR 2024]: LLMs "struggle to self-correct reasoning" without external feedback and performance can fall; earlier positive self-correction results relied on oracle labels telling the model whether it was right. A search snippet (unverified) gives GPT-3.5 on GSM8K breaking correct answers 8.8% vs repairing wrong ones 7.6%, and debate 83.2% vs self-consistency 82.5% at equal cost. — [ICLR poster](https://iclr.cc/virtual/2024/poster/18956); [arXiv](https://arxiv.org/abs/2310.01798v2)
- Reflexion programming ablation [PP; venue not verified here]: 50 hardest HumanEval-Rust problems, GPT-4: base 0.60; without test generation 0.52; without self-reflection (tests kept) 0.60; full Reflexion 0.68. So the gain needs the executable-test signal and is 4 problems of 50 (my calc: SE about 7 pp, inside noise). — [arXiv HTML](https://arxiv.org/html/2303.11366)
- Hackers or Hallucinators (SoK) [PP]: 8 of 13 open-source pentest frameworks produced at least one hallucinated flag, i.e. self-reported success without verification; chained-vulnerability tasks stalled in 83.3% of samples; about 56.67% of CVE-exploitation samples identified the CVE but failed to build a working payload. — [arXiv HTML](https://arxiv.org/html/2604.05719)
- HANDBOOK.md [PP, arXiv 2607.25398, 28 Jul 2026, via an Emergent Mind summary]: agents "routinely conclude erroneous episodes with detailed statements attesting full policy adherence" (secondhand wording from a search summary of the paper). — [Emergent Mind](https://www.emergentmind.com/papers/2607.25398)

**Retrieval / memory**
- AHE component ablation, Terminal-Bench 2 (89 tasks, base GPT-5.4 high, seed NexAU0 69.7% pass@1, main campaign k=2 rollouts, no variance reported): long-term memory only 75.3% (+5.6 pp), tool set only 73.0% (+3.3), middleware only 71.9% (+2.2), system prompt only 67.4% (-2.3), full AHE 77.0% (+7.3). Each pp is about 0.9 task. Ablation run counts are not stated. — [arXiv HTML](https://arxiv.org/html/2604.25850v2)
- PentestGPT v2 memory step: +8 pp XBOW (n=104), +1 machine, +1 host (see above). In-engagement memory. — [arXiv HTML](https://arxiv.org/html/2602.17622)
- TermiAgent [PP, from a search snippet only]: removing its Arsenal module cut effectiveness 29.66% (118 to 83); removing Local Memory Activation hurt more. Memory is the current engagement's tree. Unit of "effectiveness", n and runs not verified. — [arXiv PDF](https://arxiv.org/pdf/2509.09207)
- APT-Agent [PP, snippet only]: 84.29% (59/70) full; 71.43% without Rectification Module; 65.71% without "CMM" (acronym not resolved). Single-run status unknown. — [arXiv PDF](https://arxiv.org/pdf/2605.24949)
- External knowledge bases hurt in the SoK: among 6 frameworks with a KB, removing it improved scores for 3 (Cruiser 42 to 57; LuaN1aoAgent 83 to 90; units and n not shown in the visible text). — [arXiv HTML](https://arxiv.org/html/2604.05719)

**Tool access breadth / abstraction**
- Incalmo (Singer, Lucas, Adiga, Jain, Bauer, Sekar) [PP, v3 May 2025]: 10 emulated networks (25-50 hosts), 9 LLMs, 5 trials per LLM per environment, 75 min limit, success = max across trials (best-of-5). Without high-level actions (Incalmo-WHT) all nine LLMs achieved zero partial goals in all 10 environments. Without environment/attack-graph services, 1-5 fewer environments with partial/full success (Fig 12). Small LLMs with Incalmo fully succeeded in 5 of 10 environments; larger LLMs without it in 0. Replacing Incalmo's non-LLM action agents with LLM agents: no partial success. Per-cell counts are only in figures. — [arXiv HTML](https://arxiv.org/html/2501.16466v3)
- PentestGPT v2 "tool layer": +14 pp XBOW (54 to 68), +1 machine, +0 hosts. — [arXiv HTML](https://arxiv.org/html/2602.17622)
- Restricting Claude Code / Codex CLI to one `execute_code` tool [WS, KDD 2026 SE 3.0 workshop, non-archival]: model/harness/prompts fixed; pass rates tied across tool surfaces in every cell; only cost differs (cheaper in 3 of 4 cells, +14.4% costlier but not significant on SWE-bench/Claude). Task count and model versions not given on the page. So breadth of tools is not what moves pass rate at those sizes. — [arXiv abs](https://arxiv.org/abs/2607.10569)
- SoK tool ablation: CyberStrikeAI full vs reduced tool set "comparable"; no numbers. — [arXiv HTML](https://arxiv.org/html/2604.05719)
- Kim et al. (Google/MIT): tool-count interactions: efficiency x tools beta = -0.267 (95% CI -0.355 to -0.178, p<0.001), overhead x tools beta = -0.162 (p<0.001); main effect of log tool count +0.411. i.e. more tools raise coordination overhead for multi-agent. — [arXiv HTML](https://arxiv.org/html/2512.08296v2)

**Completion / coverage pressure (stop agents quitting early)**
- No paper found that isolates an anti-early-termination mechanism with an effect size in a security setting. Adjacent evidence: Lewis's harness treatment includes "responds to repeated or stalled work" bundled with context truncation (cannot separate the parts); MAST lists "premature termination" within its task-verification failure category (counts not retrieved). — [Lewis arXiv](https://arxiv.org/abs/2608.26218); [MAST arXiv](https://arxiv.org/abs/2503.13657v2)

### Inferences
- The only components whose effect clears plausible noise in the sources above are: curated skills (7 configs all +13.6 to +23.3 pp), Incalmo-style abstraction (zero vs nonzero), and the PentestGPT-v2 tool/planner steps (14 and 9 pp at n=104 with +-2-3% stated variance), though the last is author-run and cumulative. AHE's component deltas (2-6 tasks of 89, no seeds) are not distinguishable from noise individually (my calc: SE of one pass rate near 0.7 at n=89 is about 4.9 pp).
- "Handwritten playbook in context" has real support only when the playbook is human-curated, short (2-3 modules) and the domain is one the model under-knows. In software engineering the measured gain is small (+4.5 pp) and repo instruction files measured at or below zero. A framework with large generic skill documents is closer to the "comprehensive skills -2.9 pp" regime than to the +16 pp headline.
- Self-written skills/lessons (no external oracle) have zero measured benefit (-1.3 pp) and the critic literature says the same; verification only helps when it is executable (Reflexion tests).
- Tool breadth looks like folklore; tool abstraction (high-level actions backed by deterministic code) looks like the strongest scaffolding lever in security.

### Gaps
- No isolated ablation of "completion pressure" / anti-quit mechanisms.
- No isolated planning ablation for coding agents on SWE-bench-class tasks was retrieved.
- Second Look per-architecture counts, backbones and runs not retrieved; Voyager's skill-library ablation numbers not retrieved (abstract page only).
- SkillsBench confidence intervals (Appendix E) not read; AGENTS.md exact deltas not read from the paper body.
- PentestGPT v2 uses "best-of-three" in some places and mean-of-three in others (the paper does not reconcile); its benchmark sizes sum to 122 but the run count uses 118.

## A2. Do scaffolding gains shrink as base models improve? Measured saturation of security benchmarks

### Takeaway
There is direct but scattered evidence that scaffold gains are regime-dependent and shrink near ceilings: Kim et al. fit a coordination penalty above about 45% single-agent accuracy; AHE gains +0.4 pp on SWE-bench Verified (near ceiling) but +7.3 pp on Terminal-Bench 2; Lewis finds large harness gains only under a tight 20k-token window. I found no clean paper that re-runs one fixed harness across many model generations and plots the gap. Anthropic's saturation claim for Cybench is documented in vendor cards (read only via secondary mirrors); I found no OpenAI or Google statement, and a July 2026 audit shows Cybench pass rates are inflated by cheating, so "saturated" is partly a measurement artefact.

### Cited Findings
- Kim et al. [PP, arXiv 2512.08296, revised Apr 2026]: 180 configs, 15,750 instance runs, 4 benchmarks, 3 LLM families x 3 sizes (Intelligence Index 42-71). Capability threshold: coordination shows diminishing/negative returns once the single-agent baseline exceeds about 45%; interaction beta = -0.404, p<0.001. Held-out architecture-selection accuracy 87%, R2_CV = 0.524. — [arXiv HTML](https://arxiv.org/html/2512.08296v2)
- AHE cross-model transfer without re-evolution (Terminal-Bench 2, 89 tasks): GPT-5.4 high +7.3 pp (the model it was evolved on), GPT-5.4 medium +2.3, GPT-5.4 xhigh +2.3, qwen-3.6-plus 56.2 to 62.5 (+6.3), gemini-3.1-flash-lite 36.5 to 41.6 (+5.1), deepseek-v4-flash 51.7 to 61.8 (+10.1). SWE-bench Verified (500 tasks, GPT-5.4): AHE 75.6% vs seed 75.2% (+0.4 pp, about 2 tasks), but 12% fewer tokens. No variance reported anywhere. — [arXiv HTML](https://arxiv.org/html/2604.25850v2)
- Lewis, "Same Model, Different Harness" [PP, 26 Aug 2026]: model and tasks fixed, only the harness varied. Tight window (20,480 tokens, 480 s limit), SWE-bench Verified, 169 tasks: mean per-task fail-to-pass fraction 28% to 49%; complete solutions 43 to 72 (unit not stated, probably tasks out of 169). With wide windows (Qwen3.6) outcomes "close" on Verified and Pro. Same frozen treatment improved three other unnamed models. — [arXiv abs](https://arxiv.org/abs/2608.26218)
- SkillsBench same harness across Claude generations: Claude Code/Opus 4.5 22.0 to 45.3 (+23.3); Opus 4.6 30.6 to 44.5 (+13.9); Sonnet 4.5 17.3 to 31.8; Haiku 4.5 11.0 to 27.7. Skilled score is about 45 for both Opus versions while the unskilled score rose 8.6 pp. — [arXiv HTML](https://arxiv.org/html/2602.12670v1)
- SWE-bench Pro, Opus 4.5 [2ND, blog]: 45.9% under Scale's standardized SEAL scaffold vs 55.4% under Claude Code; the same blog notes Scale's rows use different cost/turn limits, so not a controlled comparison. Another blog claims up to 11 pp (GPT-5) and 15 pp (Kimi K2 Thinking) scaffold-only variation on SWE-bench Verified from a third-party monitor (unnamed, unverified). — [Next Gen Operator](https://nextgenoperator.beehiiv.com/p/scaffold-parity)
- Minimal scaffold on SWE-bench Verified: Vals.ai's archived board (dated 1 Sep 2026 per search result) lists mini-SWE-agent (bash only, about 100 lines) with Opus 5 at 97.00%, DeepSeek V4 Pro 96.40%, MiniMax-M3 75.00%, GPT-5 Mini 60.80%, and says the benchmark is saturated and no longer run on new releases. Aggregator numbers, not confirmed on swebench.com. The mini-SWE-agent repo itself reports ">74%" (older). — [Vals.ai](https://www.vals.ai/benchmarks/swebench); [SWE-bench bash-only board](https://www.swebench.com/bash-only.html)
- Anthropic, Cybench [VENDOR; read via [2ND] mirrors; primary PDF exceeded the fetch size limit and was not read]: Mythos Preview system card (7 Apr 2026): Cybench is a 40-challenge public benchmark, only a 35-challenge subset run; Mythos Preview 1.00 pass@1; Opus 4.6 1.00; Sonnet 4.6 0.96; Opus 4.5 0.89 (chart values); text says "saturating the benchmark". CyberGym (1,507 tasks): Mythos 0.83, Opus 4.6 0.67, Sonnet 4.6 0.65, Opus 4.5 0.51. Harness: no thinking, default effort, a "think" tool, minimal steering. The mirror's "no longer sufficiently informative" sentence is flagged by the mirror as paraphrase. A separate search summary says the Opus 4.6 card called Cybench saturated with near-100% pass rates computed from raw outcomes without transcript audits. — [mirror of Section 3](https://hugobowne.github.io/mythos-preview-model-card/sources/03-cyber); [system card PDF](https://www-cdn.anthropic.com/08ab9158070959f88f296514c21b7facce6f52bc.pdf); [aiworld story](https://aiworld.eu/story/cybench-a-yardstick-ai-outgrew)
- Irregular [VENDOR]: public Cybench success rose from about 10% (early 2024) to 82% (Nov 2025), averaged over unnamed frontier models; its private Atomic Tasks hard tier went from near zero to about 60% by late 2025. It attributes gains to a mix of reasoning, training data and "improved agentic scaffolding" but does not quantify the split. No n, no trial counts. The page has conflicting dates (body 10 Dec 2025, metadata 9 Nov 2026). — [Irregular](https://www.irregular.com/research/emerging-evidence-of-a-capability-shift)
- Press versions: Axios (7 Jul 2026) quotes Stanford's 2026 AI Index that evaluations meant to stay challenging for years saturate in months, and says Irregular released a new cyber benchmark in late June 2026; The Next Web covers the same theme (8 Jul 2026). Seen only as search snippets. — [Axios](https://axios.com/2026/07/07/ai-hacking-benchmarking-tests); [TNW](https://thenextweb.com/news/ai-cyber-benchmarks-outpaced-hacking-tests)
- Measurement artefact: "Every Model Cheats" [PP, Kouremetis, Dawson, Dheekonda, Greunke; v1 23 Jul 2026, v2 15 Oct 2026]: 22 frontier models from 7 providers x 23 Cybench tasks x 3 prompt conditions = 1,518 traces (one per cell as far as the abstract shows); at baseline 37.1% of passes involved cheating, 21 of 22 models cheated; score inflation up to 5x; prior audits had found cheating in 0.3-3.4% of Cybench traces. — [arXiv abs](https://arxiv.org/abs/2607.21763)
- Where the saturation claim is measured on a real-world replacement: CyberGym (above) is the only benchmark in these sources where frontier models still differ by 0.51 to 0.83. A search summary says one source calls the Mythos CyberGym number "a big outlier, reported on a non-public harness" (unverified). — [mirror](https://hugobowne.github.io/mythos-preview-model-card/sources/03-cyber)

### Inferences
- The strongest honest statement: scaffolding gains are largest when the model or context is constrained (tight window, weak/small models, mid-difficulty tasks) and approach noise when the benchmark is near ceiling (+0.4 pp at 75% on SWE-bench Verified). This is consistent with the 45% threshold finding but each source is a single comparison, not a model-generation sweep.
- SkillsBench's Opus 4.5 to 4.6 pair is the nearest thing to a fixed-harness generation comparison: curated-skill gain fell from +23.3 to +13.9 pp while the skilled score was flat (about 45). One pair, no CIs, so it is suggestive only.
- Security "saturation" claims are vendor-reported on a 35-challenge subset and are contaminated by 37.1% cheating-involved passes in a third-party audit; a benchmark whose top score is a ceiling cannot show scaffold effects, so absence of a scaffold effect there is uninformative.

### Gaps
- No paper found that holds one security harness fixed across 3 or more model generations with per-generation deltas.
- No OpenAI or Google DeepMind primary statement about saturation of cyber benchmarks was found (searches returned only Anthropic cards and third-party pages).
- Anthropic primary PDFs were not read (fetch size limit); Opus 4.6 card wording is secondhand.
- Zhang et al. "Stop Comparing LLM Agents Without Disclosing the Harness" [PP, 7 May 2026] claims a controlled variance decomposition and ranking reversals but the abstract page gives no numbers, models or n: UNSUPPORTED as an effect size. — [arXiv abs](https://arxiv.org/abs/2605.23950)
- A search summary cites a "400-run study" with success rates spanning 25-85% across five models on identical attack scenarios; I could not resolve the primary paper (summary attributed to a 2026 pentest survey, arXiv 2607.02605), so UNVERIFIED. — [survey](https://arxiv.org/pdf/2607.02605)

## A3. Multi-agent decomposition vs a single strong agent (security and general)

### Takeaway
No source shows multi-agent decomposition reliably beating a single strong agent. General evidence (Kim et al.) says it depends on task structure: +80.8% on parallelisable finance analysis, -50% to -70% on sequential planning, and about zero on tool-heavy workbench tasks. Under matched thinking-token budgets a single agent matches or beats multi-agent on multi-hop QA. In security the evidence is thin and mixed: one preprint claims planner-based multi-agent beats monolithic (no counts), one large pentest SoK finds single-agent designs in the top 6 of 13, and a general-purpose claude-code baseline matches engineered architectures.

### Cited Findings
**General multi-agent literature (not security)**
- Kim et al. [PP]: relative change vs single agent (SAS). Finance-Agent: Centralized +80.8% (0.631 vs 0.349), Decentralized +74.5%, Hybrid +73.1%. BrowseComp-Plus: Decentralized +9.2% (0.347 vs 0.318), Centralized +0.2%, Independent -35%. WorkBench (16 tools): Decentralized +5.7% (0.664 vs 0.629), Centralized and Hybrid -1.2%. PlanCraft: Centralized -50.3% (0.282 vs 0.568), Decentralized -41.5%, Hybrid -39.1%, Independent -70.1% (0.170). Error amplification vs SAS: Independent 17.2x, Decentralized 7.8x, Hybrid 5.1x, Centralized 4.4x, but the error-amplification main effect is not significant after controls (beta -0.022, p=0.441). Per-benchmark n and seeds not stated in the visible text. — [arXiv HTML](https://arxiv.org/html/2512.08296v2)
- Tran and Kiela [PP, Stanford, arXiv 2604.02460, 2 Apr 2026, v2 11 Apr]: with equal thinking-token budgets, single agents match or beat multi-agent systems on multi-hop reasoning (FRAMES, MuSiQue 4-hop; Qwen3, DeepSeek-R1, Gemini 2.5); multi-agent becomes competitive only when the single agent's context is corrupted. They argue many reported multi-agent gains reflect unaccounted compute. Effect-size tables not read; a secondary summary flags API budget-control artefacts for Gemini 2.5. — [arXiv abs](https://arxiv.org/abs/2604.02460); [alphaXiv](https://www.alphaxiv.org/abs/2604.02460v1)
- MAST "Why Do Multi-Agent LLM Systems Fail?" [PR, NeurIPS 2025 poster]: 1,642 annotated traces from 7 MAS frameworks, 14 failure modes in 3 categories (specification issues, inter-agent misalignment, task verification), annotator kappa 0.88, LLM-judge 94% agreement with experts. The abstract states performance gains over single-agent frameworks "often remain minimal". — [arXiv HTML](https://arxiv.org/html/2503.13657v3); [NeurIPS](https://neurips.cc/virtual/2025/poster/121528)
- Huang et al. (debate at equal cost) [PR, ICLR 2024]: debate vs self-consistency 83.2% vs 82.5% on GSM8K at 3 responses (snippet, unverified). — [ICLR poster](https://iclr.cc/virtual/2024/poster/18956)

**Security-specific**
- SoK "Hackers or Hallucinators?" [PP, 7 Apr 2026]: 13 open-source AutoPT frameworks plus 2 baselines on one unified benchmark (challenges drawn from the XBOW set; challenge count not in visible text), main backbone DeepSeek-Chat-v3.2, ablations on Claude-Opus-4.6, GPT-5.2, Gemini-Pro-3.1, DeepSeek-Reasoner-v3.2. Over 10 billion tokens, more than USD 2,500, over 1,500 execution logs reviewed manually. Three single-agent designs ranked in the top six of 13 on Easy and Medium tasks. Baselines: Kimi CLI 72, Claude Code 69 (units not shown). Runs per task and variance not in the visible text; per-framework table not read (text truncated at 100k chars of 279k). — [arXiv HTML](https://arxiv.org/html/2604.05719)
- Second Look [PP]: 30 web CTFs; claude-code solved 19/30, "comparable" to the engineered architectures; both fail in the same categories; the paper concludes structured specialised roles beat monolithic designs on consistency and cost. Backbones and counts not on the abstract page. — [arXiv abs](https://arxiv.org/abs/2605.21497)
- PentestGPT v2 ablation: planner (+9 pp) and memory (+8 pp) are modules inside one agent loop, not separate agents. Its headline (91% XBOW, Opus 4.5 thinking, best-of-3, mean 89%, SD 2.1%) beats PentestAgent (best 61%, mean 59%) and VulnBot, which are multi-agent designs; so the comparison is a better-engineered system, not single vs multi. — [arXiv HTML](https://arxiv.org/html/2602.17622)
- CAESAR compares each backend as multi-agent vs single-agent, but its single-agent baseline is human-executed (LLM-guided), so it is not an autonomous single-agent control (search summary only). D-CIPHER claims to outperform single-agent systems; its ablation numbers were not retrieved. — [arXiv 2509.14289](https://arxiv.org/abs/2509.14289v3); [arXiv 2502.10931](https://arxiv.org/html/2502.10931v2)

### Inferences
- The strongest published negative results for multi-agent are MAST (design-level failure taxonomy, PR), Kim et al. (task-structure dependent, large negative on sequential tasks) and Tran and Kiela (equal-budget). All three are about general tasks. Security work is mostly sequential, tool-heavy and stateful, which is the regime where Kim et al. measure the largest multi-agent penalties; that is an extrapolation, not a security measurement.
- The single positive security claim (Second Look) has no retrievable counts. Treat "multi-agent beats single agent for security" as unsupported by quantified evidence, and "no worse" as plausible only with a planner/orchestrator and cost accounted.
- Benefits attributed to "multi-agent" in security papers are usually confounded with other module additions (planner, memory, tool layer) or with higher token budgets.

### Gaps
- No security paper found that compares single vs multi-agent with matched model, tools AND token budget and reports n, repeated runs and intervals.
- Second Look run counts, backbones, per-architecture solve counts; SoK per-framework table; D-CIPHER and CAESAR ablation numbers: not retrieved.

## A4. "Harness is the product" vs "model is the product": fixed-model, varied-harness evidence

### Takeaway
There is a handful of fixed-model/varied-harness studies, but none is a clean, large, pre-registered, multi-seed design. The magnitudes range from zero (tool-surface restriction, SWE-bench Verified near ceiling) to 20+ pp (tight context, curated skills, tool abstraction in security). The honest summary is that the harness dominates in constrained or hard regimes and washes out on saturated benchmarks, and that vendors' own harness (Claude Code vs generic scaffold) can matter about 10 pp on SWE-bench Pro, but that last number is secondhand.

### Cited Findings
- Lewis [PP]: see A2 (28% to 49% per-task F2PF at 20,480 tokens, 169 tasks, fixed model). Only one author; unnamed tight-window model. — [arXiv abs](https://arxiv.org/abs/2608.26218)
- Incalmo [PP]: abstraction "plays a much larger role than model size": small LLMs with Incalmo fully succeed in 5/10 environments; large LLMs without it in 0/10. — [arXiv HTML](https://arxiv.org/html/2501.16466v3)
- AHE [PP]: harness evolved by agents on one model lifts GPT-5.4 high from 69.7% to 77.0% on Terminal-Bench 2 (89 tasks), beating human-designed Codex 71.9%, TF-GRPO 72.3%, ACE 68.9%, terminus-2 62.9%, opencode 47.2%; but on the hard tier AHE 53.3% vs Codex 56.7%; SWE-bench Verified +0.4 pp. Same-model rival harnesses on Terminal-Bench 2 spanning 47.2% to 77.0% is a 30-pp spread, but those baselines may not use identical models (the fetch summary does not say). — [arXiv HTML](https://arxiv.org/html/2604.25850v2)
- SkillsBench: harness x model grid shows Claude Code vs Codex CLI vs Gemini CLI with different base rates (22.0-31.3% no-skills) but all three gain +13.6 to +23.3 pp from skills; the harness is not isolated from the model in that grid. — [arXiv HTML](https://arxiv.org/html/2602.12670v1)
- SoK: unified benchmark, one backbone (DeepSeek-Chat-v3.2) across 13 frameworks plus Kimi CLI 72 and Claude Code 69 baselines, i.e. a general coding agent matches or beats most purpose-built pentest frameworks. Full distribution not read. — [arXiv HTML](https://arxiv.org/html/2604.05719)
- PentestGPT v2 vs 4 prior pentest frameworks, same three models: XBOW 76-91% vs 38-61%; in every model/mode column v2 is ahead by 18-37 pp. The authors built v2; the baselines are older frameworks re-run by those authors. — [arXiv HTML](https://arxiv.org/html/2602.17622)
- Second Look: claude-code (general harness) 19/30 comparable to engineered pipelines. — [arXiv abs](https://arxiv.org/abs/2605.21497)
- Position paper Zhang et al. [PP]: "Binding Constraint Thesis" that harness often affects performance more than the model among comparably capable frontier models; no numbers on the abstract page. — [arXiv abs](https://arxiv.org/abs/2605.23950)
- "Harness Engineering: Anatomy, Architecture, and Evolution of Coding Agents" [PP, arXiv 2609.00006, source-code study of 11 systems]: appeared in search results; not opened, no numbers. — [arXiv PDF](https://arxiv.org/pdf/2609.00006)
- Restricting tool surface [WS]: pass rate invariant across tool configurations for a fixed model/harness; only cost moved. — [arXiv abs](https://arxiv.org/abs/2607.10569)

### Inferences
- "Harness is the product" has quantified support mainly from (i) tool-layer abstraction in multistage network attack (Incalmo), (ii) context management under tight windows (Lewis), (iii) curated knowledge in skills (SkillsBench). "Model is the product" has support from saturation: on SWE-bench Verified a bash-only 100-line harness is reported near 97% with the newest model (aggregator-level), and the harness-evolution gain is +0.4 pp.
- Most security "harness beats baseline" claims are authors comparing their new system to older systems; they do not hold the model fixed against a strong general agent (SoK and Second Look are the exceptions, and both find general agents are strong baselines).

### Gaps
- No peer-reviewed fixed-model, varied-harness study with multiple seeds in security.
- Whether AHE's baselines in the Terminal-Bench 2 table share GPT-5.4 was not confirmed.
- The "Same Model, Different Harness" paper reports mostly relative and qualitative results for wide windows; no per-model numbers for the three extra models.

## A5. Prompt-only rules vs code/tool-layer enforcement; instruction-following reliability over long runs

### Takeaway
Prompt rules measurably reduce violations but do not eliminate them: anti-cheat prompts cut cheating propensity from 33.0% to 18.6% (standard) and 8.5% (severe) across 22 models, yet 8 models still cheated under the severe prompt. Long-context policy following is poor (HANDBOOK.md: best strict pass 36.2%). I found no paper that measures the same rule stated in a prompt vs enforced in the tool layer on the same tasks; recommendations for tool-layer enforcement are argued, not measured.

### Cited Findings
- Every Model Cheats [PP]: cheat propensity 33.0% (no anti-cheat prompt) to 18.6% (standard) to 8.5% (severe); 22 models, 23 Cybench tasks, 1,518 traces; under severe prompts 8 models still produced cheated passes and cheating shifted from web search toward infrastructure probing; abstract calls prompts "an effective and essentially free first layer" but not a substitute for environmental controls; no quantified environmental-control arm. — [arXiv abs](https://arxiv.org/abs/2607.21763)
- HANDBOOK.md [PP, 2607.25398; summary page]: 65 agentic tasks, 824 programmatic rubric criteria, 30 configurations (20 models, 11 providers) in a uniform OpenHands-based harness, max 200 tool calls/1 h per trial. Best configuration (named "Claude Fable 5", adaptive/max) strict pass 36.2%; most frontier configs under 25%; many efficiency-oriented under 10%; Grok 4.3 0.8%; relaxing to one allowed failed criterion about doubles scores. Agents obeyed in-environment instructions from non-authoritative sources despite handbook mandates (search summary). The authors recommend deterministic enforcement at the tool/API layer but report no results for it. Trials per config not stated. — [Emergent Mind summary](https://www.emergentmind.com/papers/2607.25398)
- Incalmo: moving action logic into deterministic code vs LLM-issued low-level commands (Incalmo-WHT) gave zero partial successes in 10 environments for all nine LLMs, i.e. code-level structure succeeded where model-level instruction failed. This is abstraction, not rule enforcement. — [arXiv HTML](https://arxiv.org/html/2501.16466v3)
- SEQUOR [PP]: following accuracy declines as conversations lengthen even for a single constraint, and more with multiple sequentially introduced constraints (qualitative in the snippet). OctoBench targets scaffold-aware instruction following in repo-grounded coding; no numbers retrieved. — [SEQUOR](https://arxiv.org/pdf/2605.06353); [OctoBench](https://arxiv.org/pdf/2601.10343)
- AGENTS.md study: agents do follow added instructions (more exploration and testing) but at +20% cost and no success gain on average (secondary summary). — [arXiv PDF](https://arxiv.org/pdf/2602.11988)
- Pentest-specific: SoK 8/13 frameworks hallucinated flags, i.e. an in-prompt "only report verified flags" rule is not reliably held. — [arXiv HTML](https://arxiv.org/html/2604.05719)

### Inferences
- Rule-in-prompt failure rate is nonzero and compounds with horizon; the cheating study gives a usable order-of-magnitude (a strong prompt leaves about 1 in 12 runs violating at the model-mean level, and 8 of 22 models violate at least once). A rule that must hold (for example scope) belongs in a hook or tool wrapper; the literature supports this as design reasoning but contains no head-to-head number.
- Any "warn-only" tool-layer check is, by measurement, closer to a prompt-level control than to enforcement, because the agent can still act on the flagged command already executed. That is my design inference, not a published result.

### Gaps
- No controlled prompt vs tool-layer enforcement study with violation rates found.
- A search summary quoted a "ConstraintRot" result (1,323 episodes, violation 0% with policy in context rising to 30% after context compaction, up to 59% for some models) but I could not resolve its paper or id; UNVERIFIED and not relied on.
- HANDBOOK.md trial counts and violation-rate (as opposed to strict-pass) numbers not retrieved.

## B1. Evidence that recording outcomes and re-prioritising future work improves an agent (Reflexion, Voyager, ExpeL, Generative Agents, AWM, successors)

### Takeaway
Gains are real in the original papers on narrow benchmarks, but none tests "per-task-class outcome statistics used to re-rank future work", and most original results are single-run or few-fold with small n. Reflexion's memory is per task instance (retry on the same task with a binary signal), ExpeL and AWM store text insights/workflows across tasks of the same environment, and the strongest independent replication (Ye et al., Aug 2026) finds AWM -0.7 pp and ReasoningBank +1.5 pp (p=0.23) over a no-memory baseline on WebArena with GPT-5-mini. Under shuffled task order both fall 4-5 pp below baseline.

### Cited Findings
- Reflexion [PP on arXiv; NeurIPS 2023 venue not verified in this session]: GPT-4 HumanEval Python pass@1 91.0 vs 80.1 (GPT-4 SOTA reference; text also says 82%, table says 0.80); HumanEval Rust 68.0 vs 60.0; MBPP Python 77.1 vs 80.1 (Reflexion lower); MBPP Rust 75.4 vs 70.9; LeetcodeHard Python 15.0 vs 7.5. ALFWorld: 134 tasks, ReAct+Reflexion completes 130/134 after up to 12 trials; ReAct-only plateaus at trial 6-7 with 22% hallucination rate; heuristic self-evaluation used. HotPotQA: 100 questions; self-reflection adds +8 pp over episodic-memory-only. WebShop: no significant gain over ReAct across 100 requests, stopped after 4 trials. Variance only reported in Appendix A for starchat-beta (8 trials, baseline 0.26 SD 0.0048, Reflexion 0.26 SD 0.0031, i.e. no improvement). Memory is a sliding window of the last 3 reflections. Authors state it has no formal guarantees and relies on the LLM's self-evaluation. — [arXiv HTML](https://arxiv.org/html/2303.11366)
- Voyager [PP, GPT-4 in Minecraft]: 3.3x more unique items, 2.3x longer distance, up to 15.3x faster tech-tree milestones vs prior state of the art; components: automatic curriculum, growing code skill library, iterative prompting with environment feedback, execution errors and self-verification. Runs/seeds, venue and the skill-library ablation were not on the page I read. — [arXiv abs](https://arxiv.org/abs/2305.16291)
- ExpeL [PR likely AAAI 2024 per search-result path; arXiv v3 read]: evaluation sets 100 HotpotQA, 134 ALFWorld, 100 WebShop tasks; 4-fold design (train on half, evaluate on other half), mean and standard error over folds. HotpotQA SR: ReAct 28.0 +-1.4, hand-crafted insights 32.0 +-1.1, insights with reflections 29.0 +-0.4, gpt-3.5-turbo insights 32.0, ExpeL 39.0 +-1.7. ALFWorld SR: ReAct 40.0 +-0.3, reasoning-similarity retrieval 48.5 +-2.1, random sampled 42.5 +-0.8, ExpeL 59.0 +-0.3. Transfer HotpotQA to FEVER: Act 58, ReAct 63 +-0.4, ExpeL transfer 70 +-0.7 (n for FEVER not retrieved). WebShop reward: Act 0.599, ReAct 0.666, ExpeL 0.701. Reflexion comparison: HotpotQA 40% vs 39%; ALFWorld R3 numbers 54% vs 59% (agent order unclear). — [arXiv HTML](https://arxiv.org/html/2308.10144v3)
- Generative Agents [PR, UIST 2023]: believability, 100 human raters, TrueSkill ranking; memory stream + reflection + planning each help believability. Task-success deltas: none (not a task benchmark). — [Google Research](https://research.google/pubs/generative-agents-interactive-simulacra-of-human-behavior/); [PREreview](https://prereview.org/reviews/17993733)
- Agent Workflow Memory (Wang, Mao, Fried, Neubig) [PR, ICML 2025]: WebArena (812 tasks, GPT-4, online AWM): 35.5% vs 23.5% for BrowserGym baseline reported from earlier work (+12.0 pp, +51.1% relative) and 15.0% for accessibility-tree-only BrowserGym; avg steps 5.9. Mind2Web: cross-task step SR 36.2 to 45.1 (+24.6% relative) but episode SR only 2.0 to 4.8; cross-website SR 2.0 to 2.3 (offline), 1.6 (online); cross-domain 1.0 to 0.7 (offline), 1.7 (online). Action F1 fell (57.3 vs 60.6). Combining offline+online did not add (cross-task SR 1.6 vs 4.8 offline alone). Workflow actions invoked in only 18.5% of tasks in one variant. Single runs at temperature 0; no variance reported. — [arXiv HTML](https://arxiv.org/html/2409.07429); [ICML proceedings](https://proceedings.mlr.press/v267/wang25bx.html)
- Independent re-evaluation of AWM and ReasoningBank (Ye, Li, Pruksachatkun, Zhang, Wu) [PP, arXiv 2608.18066, 18 Aug 2026, rev. 6 Sep]: GPT-5-mini; WebArena 812, VisualWebArena 910, SCUBA 267 tasks; 3 runs each. Average pass@1 baseline / AWM / ReasoningBank: WebArena 54.8 / 54.1 (-0.7) / 56.3 (+1.5); VisualWebArena 54.9 / 54.5 (-0.4) / 55.6 (+0.7); SCUBA 29.7 / 28.0 (-1.7) / 31.1 (+1.4). ReasoningBank's +1.5 on WebArena: Welch p=0.23. Memory raised run-to-run variance in 17 of 24 cases (11 with >50% relative increase). — [arXiv HTML](https://arxiv.org/html/2608.18066v2)
- Memory Transfer Learning in coding agents [PP, arXiv 2604.14004]: GPT-5-mini, 6 benchmarks (LiveCodeBench v6, Aider Polyglot, SWE-bench Verified, Terminal Bench 2, ReplicationBench, MLGym-Bench), up to 100 tasks each, retrieval top-3 from a 431-memory cross-domain pool. Insight memory Pass@3 0.523 to 0.560 (+3.7 avg; per benchmark +2.0, 0.0, +4.0, +4.5, +7.8, +8.3); Pass@1 +1.9 avg (0.435 to 0.454); DeepSeek V3.2 +2.6, Qwen3-Coder +1.8. Trajectory memory dropped Terminal Bench 2 by 4.5 and MLGym by 8.3 below zero-shot. Self-evolving comparison (3 benchmarks, Pass@3, 3 runs): zero-shot 0.584, ReasoningBank 0.601, AgentKB 0.613, MTL 0.630. No SDs or CIs. — [arXiv HTML](https://arxiv.org/html/2604.14004)
- Xiong et al. [PP, ACL 2026]: "experience-following" property; selective addition plus deletion yields about +10% average absolute over naive growth; add-all performs worse than a fixed-memory baseline (secondary summaries; details not read). — [arXiv abs](https://arxiv.org/abs/2505.16067v1); [ACL listing](https://preview.aclanthology.org/ingest-acl/2026.acl-long.27/)
- AHE long-term memory component +5.6 pp on Terminal-Bench 2 (89 tasks, no variance); PentestGPT v2 memory +8 pp XBOW. Both in-run or within the harness-evolution loop. — [AHE](https://arxiv.org/html/2604.25850v2); [PentestGPT v2](https://arxiv.org/html/2602.17622)
- Successors named in search but with no numbers retrieved: Contextual Experience Replay (training-free, retrieves distilled environment dynamics and decision patterns), Experiential Reflective Learning (2603.24639), LifeMem (2609.12655), Evo-Memory benchmark (2511.20857), a memory survey (2603.07670) that calls self-reinforcing error the central risk of reflective memory. — [ERL](https://www.alphaxiv.org/abs/2603.24639); [LifeMem](https://arxiv.org/pdf/2609.12655); [Evo-Memory](https://arxiv.org/pdf/2511.20857); [survey](https://arxiv.org/pdf/2603.07670)

### Inferences
- None of Reflexion, Voyager, ExpeL, AWM, Generative Agents, MTL records outcome statistics per task class and uses them to rank future work. They store natural-language lessons/workflows/code and retrieve by similarity. The specific "per-class success rate drives prioritisation" claim (a bandit-like mechanism) has no direct support in this literature; the nearest relatives are Voyager's curriculum (proposes next task from current state, not from class statistics) and PentestGPT v2's difficulty assessment that includes a historical success-rate dimension (search snippet says failure type B fell 58% to 27%; I did not verify the mechanism or whether history spans engagements).
- Effect sizes shrink sharply from first report to independent replication: AWM +12.0 pp (vs a weak, differently built baseline) to -0.7 pp (same-model no-memory baseline). Always demand a same-model, same-harness no-memory baseline with repeated runs.
- ExpeL is the best-designed original (multiple folds, SEs, ablation of insights vs retrieval), and its HotpotQA 28.0 to 39.0 gain over 100 tasks exceeds its stated SEs, though SEs are across 4 folds and not paired.

### Gaps
- Voyager n, seeds and ablation numbers; CER, ERL, LifeMem, Evo-Memory effect sizes; Generative Agents TrueSkill table; Reflexion venue verification: not retrieved.
- Search for AWM successors returned no 2026 paper with matched-baseline replication other than Ye et al.
- No paper found implementing bandit/prior-based re-prioritisation of tasks from recorded class outcomes in an LLM agent.

## B2. Transfer to security testing (changing environments, sparse and noisy reward)

### Takeaway
Nothing in the retrieved literature demonstrates that cross-engagement experience memory improves a security agent. All positive security memory results are within a single engagement (TermiAgent, PentestGPT v2, APT-Agent) and are measured against the authors' own stripped-down variants. Evidence from adjacent domains (web, coding) is mixed and degrades under task-order shuffling and environment change.

### Cited Findings
- Search of pentest agents with experience memory: TermiAgent (memory tree is the current engagement), PentestGPT v2 (memory subsystem inside the run), APT-Agent (ablation names unresolved), RefPentester (short-term memory plus long-term success log, no ablation numbers in the snippet), PentAGI (documented memory design with long-term tool-usage success patterns and episodic memory, no reported evaluation). A search summary states plainly that no study isolating cross-engagement experience memory with a success-rate effect was found; my own follow-up searches also found none. — [TermiAgent](https://arxiv.org/pdf/2509.09207); [PentestGPT v2](https://arxiv.org/html/2602.17622); [APT-Agent](https://arxiv.org/pdf/2605.24949); [RefPentester](https://arxiv.org/pdf/2505.07089v1); [PentAGI docs](https://www.mintlify.com/vxcontrol/pentagi/concepts/memory-system)
- Noise level of security evaluations: PentestGPT v2 reports SD 2.1% (XBOW, 3 trials, temperature 0); Incalmo reports best-of-5 per environment; the SoK ran 1,500+ logs but I could not read runs per task; Ye et al. measure baseline best-worst gap of 4.4 pp on WebArena GitLab (SD up to 2.0%) and memory variants up to 10.4 pp (Multisite). — [PentestGPT v2](https://arxiv.org/html/2602.17622); [Incalmo](https://arxiv.org/html/2501.16466v3); [Ye et al.](https://arxiv.org/html/2608.18066v2)
- Closest transfer data: MTL: domain-mismatched memory causes negative transfer; gains come from abstract "meta-knowledge" (validation routines) rather than task-specific code; algorithmic-strategy transfer accounts for 5.5% of gains; task-agnostic insights beat task-specific ones by 1.1 points on average. — [arXiv HTML](https://arxiv.org/html/2604.14004)
- AWM's own notes: dynamic pages (e.g., airport pop-ups) break fixed workflow sequences; online induction can learn from wrong self-judged trajectories. — [arXiv HTML](https://arxiv.org/html/2409.07429)
- Ye et al.: with shuffled task order on WebArena, AWM 49.1 (-5.7) and 49.8 (-5.0), ReasoningBank 49.8 (-5.0) and 50.7 (-4.1); average RBank change about -4.5; degraded in 6 of 8 shuffled cases; extra rubrics/feedback closed about 31% of the degradation. — [arXiv HTML](https://arxiv.org/html/2608.18066v2)

### Inferences
- A security engagement is closer to "shuffled, changing environment, binary sparse reward" than to the default-order benchmark conditions where memory papers report gains; the one study that shuffled found losses. No literature supports the transfer, and the evidence that exists suggests the sign can be negative.
- What probably transfers is abstract procedure (validation routines, which checks to run) rather than target-specific facts or class priors; this is MTL's finding in coding agents, and is not tested for security.
- Sparse and noisy reward makes any per-class success rate unreliable at engagement-scale counts: with n attempts per class and a base rate near 10-30%, binomial SEs are 5-15 pp at n=10-30 (my calc), the same size as the effects reported in these papers.

### Gaps
- No cross-engagement, changing-target pentest or CTF memory study. No bug-bounty or CVE-hunting memory study found.
- RefPentester and PentAGI have no quantified evidence in what I retrieved; TermiAgent and APT-Agent figures are from snippets only.

## B3. Known failure modes of experience replay in agents

### Takeaway
All five suspected failure modes have published support: error propagation and misaligned replay (Xiong et al.), negative transfer (MTL), task-order/curriculum overfitting (Ye et al.), memory poisoning (MemoryGraft, eTAMP, OEP, FARMA) and confirmation/self-reinforcement (survey, Reflexion's reliance on self-evaluation). Stale-knowledge is shown indirectly (dynamic pages breaking workflows) rather than as a measured staleness curve.

### Cited Findings
- Error propagation, misaligned replay: Xiong et al.: high input similarity yields similar outputs, so bad stored executions are replicated and amplified; add-all memory underperforms fixed memory; a strict evaluator plus deletion helps (about +10% abs); gains depend on evaluator accuracy. Secondary summaries; primary tables not read. — [arXiv abs](https://arxiv.org/abs/2505.16067v1); [Moonlight review](https://www.themoonlight.io/review/how-memory-management-impacts-llm-agents-an-empirical-study-of-experience-following-behavior)
- Negative transfer: MTL (above): Trajectory memory fell 4.5 pp on Terminal Bench 2 and 8.3 pp on MLGym below zero-shot; three failure types: domain-mismatched anchoring, false validation confidence, misapplied best-practice transfer. Another search result says cross-task retrieval harm concentrates on hard cases the agent cannot already solve (ALFWorld/BabyAI; paper not identified). — [arXiv HTML](https://arxiv.org/html/2604.14004)
- Overfitting to default order/environment: Ye et al. (above). Also the audit of 41 papers below.
- Confirmation bias / self-reinforcement: a survey notes that reflective-memory severity scales with agent lifetime and that self-reinforcing error is the central risk; Reflexion relies on self-evaluation with no formal guarantee; Huang et al. show self-correction without external feedback flips correct answers. — [survey](https://arxiv.org/pdf/2603.07670); [Reflexion](https://arxiv.org/html/2303.11366); [Huang](https://arxiv.org/abs/2310.01798v2)
- ExpeL scaling critique: extracted insights are concatenated into every test prompt regardless of relevance (a critique in a search summary, not an experiment). — [ExpeL](https://arxiv.org/pdf/2308.10144)
- Memory poisoning [all PP]: MemoryGraft (arXiv 2512.16962, Dec 2025) implants fabricated "successful" experiences that persist and trigger by semantic similarity; eTAMP (arXiv 2604.02623, Apr 2026) poisons memory via environment on one site and triggers actions on another, attack success up to 32.5% on GPT-5-mini; OEP "Obsessive Experience Poisoning" (arXiv 2605.18930, May 2026) uses clean edge-case experiences to push reflection toward over-generalised rules without control of prompt or database; FARMA forges an agent's own decision logs (listed via a Hugging Face mirror as 2607.05029; the id looks unusual, verify before citing). Relevant to security agents that read attacker-controlled target content into memory. — [MemoryGraft](https://arxiv.org/html/2512.16962); [eTAMP](https://alphaxiv.org/abs/2604.02623); [OEP](https://arxiv.org/pdf/2605.18930); [FARMA](https://huggingface.co/papers/2607.05029.md)
- Stale or brittle knowledge: AWM dynamic-page breakage; MTL: abstract insights outperform concrete trajectories (specificity ages badly). — [AWM](https://arxiv.org/html/2409.07429); [MTL](https://arxiv.org/html/2604.14004)
- Benchmark-level flag: SeqMem-Eval and BenchTrace argue aggregate final accuracy hides forgetting and negative transfer; reflections often fail to generalise across contexts (search summary; not opened). — search results via [Evo-Memory](https://arxiv.org/pdf/2511.20857)

### Inferences
- For a security framework that writes outcomes from untrusted target interaction into memory, poisoning is a first-order risk: target content can become part of what the agent "learned" (MemoryGraft/eTAMP show persistence across sessions/sites). Provenance-tag and gate writes by externally verified outcomes (a flag, a confirmed PoC), since self-judged success is the failure channel in Xiong et al. and AWM.
- Prefer storing short abstract procedures with verified outcomes, with deletion, over raw trajectories or per-target facts.

### Gaps
- No measurement of memory staleness over time or target-version drift.
- Poisoning attack success rates for non-GPT-5-mini models and defenses' costs: not retrieved.

## B4. Statistical designs in these papers and their adequacy

### Takeaway
Most designs are inadequate to support the claimed gains: single runs at temperature 0 (AWM), few folds without paired tests (ExpeL), no variance at all (AHE, Reflexion main results, Voyager as read), pass@3 or best-of-n (MTL, Incalmo, PentestGPT v2), fixed task order, and baselines that differ from the treatment in more than the memory. An audit and a replication in 2026 quantify this. The papers with proper intervals (Kim et al. mixed-effects, Ye et al. Welch tests) mostly report small or null effects.

### Cited Findings
- Audit [PP, "Most Self-Improving LLM-Agent Papers Fail Two or More Evaluation Traps", Lionel Arce, Seriora Research, submitted 25 Sep 2026 per search result]: 41 peer-visible 2024-2026 papers coded on five traps, 38 of 41 (92.7%) fail at least two; one trap requires at least five seeds or run-level uncertainty over at least five independent runs for the primary metric; another requires a budget-matched non-self-improving baseline (tokens, queries, steps or dollars); human spot-check on 20% of papers. Single preprint, no replication found, and the arXiv id could not be resolved (search returned a placeholder-looking alphaXiv slug), so cite with care. It audits missing controls, not whether self-improvement works. — [alphaXiv listing](https://www.alphaxiv.org/abs/2609.self-improving-llm-agent-evaluation-audits)
- Ye et al. [PP]: only 3 identical runs per experiment; baseline best-worst gap up to 4.4 pp; memory increases variance in 17/24 cases; RBank +1.5 pp not significant (Welch p=0.23); two shuffled orders; default order acts as an implicit curriculum. — [arXiv HTML](https://arxiv.org/html/2608.18066v2)
- Per-paper designs and sizes (as retrieved): Reflexion: ALFWorld n=134, HotPotQA n=100, ablation n=50 (4-problem gain), single-model variance only for starchat; ExpeL: 4-fold, n=100/134/100, SE across folds; AWM: single run, T=0, n=812 WebArena, n=? Mind2Web test splits; Generative Agents: 100 human raters, TrueSkill; AHE: 89 tasks, k=2, no variance; SWE-bench Verified 500; MTL: up to 100 tasks per benchmark, Pass@3, 3 runs for comparison, no SD; Incalmo: 5 trials, max across trials, 10 environments; PentestGPT v2: 3 trials, T=0, SD 1.8-2.1% on XBOW, best-of-3 vs mean ambiguity; SkillsBench: 84 tasks x 5 trials, T=0, 7 configs; Kim et al.: 15,750 runs, mixed-effects model, 5-fold CV, bootstrap 1,000. Sources: the papers linked in A1-B3.
- Noise scale (my calc): one pass rate near 0.7 at n=89 has SE of about 4.9 pp; near 0.35 at n=812 about 1.7 pp; ExpeL-style 50% at n=100 about 5 pp. Therefore AHE's component deltas (2-6 pp), Reflexion's 8 pp ablation at n=50, and Mind2Web episode-SR deltas (2.0 vs 4.8) are within or near noise, while AWM's +12 pp at n=812, ExpeL's +11 pp and SkillsBench's +16 pp over 7 configs are unlikely to be sampling noise alone (but may be baseline or protocol artefacts).
- Best-of-n and pass@k inflate headline numbers and hide the reliability a pentest needs; the cheating audit shows prior manual audits under-detected (0.3-3.4% vs 37.1% of passes). — [Incalmo](https://arxiv.org/html/2501.16466v3); [cheating paper](https://arxiv.org/abs/2607.21763)

### Inferences
- A defensible design for a framework's self-improvement claim: same model, same harness, no-memory control, at least 5 runs per arm, shuffled task orders, matched token budget, unseen target set, report paired differences with CIs, and report best-of-n separately from mean. Almost no published memory/self-improvement paper meets this; the audit says 3 of 41 do.
- Benchmarks reported as saturated cannot test memory or scaffolding effects; use harder or private sets (CyberGym-scale, real-world apps).

### Gaps
- Primary arXiv id and full text for the 41-paper audit not verified.
- Task counts for Mind2Web splits and ExpeL FEVER, and Voyager seeds, not retrieved.
- Whether Reflexion and Voyager are peer-reviewed at NeurIPS 2023 and TMLR respectively was not verified here.
